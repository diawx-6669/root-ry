# Развёртывание RootRy

Продакшен: [root-ry.onrender.com](https://root-ry.onrender.com) — Render (веб-сервис на Go)
плюс внешний PostgreSQL (Supabase).

## Переменные окружения

| Переменная     | Обязательна | Что делает                                                        |
|----------------|-------------|-------------------------------------------------------------------|
| `DATABASE_URL` | да          | Строка подключения к PostgreSQL. Без неё процесс не стартует.      |
| `JWT_SECRET`   | да          | Ключ подписи токенов. Не задан — берётся дефолт, и в лог уходит предупреждение. На проде это дыра: подписать токен админа сможет любой, кто знает исходники. |
| `PORT`         | нет         | Render подставляет сам. Локально по умолчанию 8080.                |
| `ADMIN_PROMO`  | нет         | Промокод, выдающий права администратора (10 активаций). По умолчанию `ADMIN240411` — на проде лучше задать свой. |
| `GEMINI_API_KEY` | нет       | Ключ Google Gemini для вкладки «Ассистент». Не задан — вкладка открывается, но на первое же сообщение отвечает, что ассистент не настроен. Ключ читает только сервер: в браузер он не попадает. |
| `GEMINI_MODEL` | нет         | Модель ассистента. По умолчанию `gemini-2.5-flash`. |
| `KSPOYA_DEMO`  | нет         | Демонстрационный режим КСПОЯ для защиты. `1` включает эндпоинт `/api/kspoya/demo-fill` и сочетание **Ctrl + Shift + Alt + W** на странице теста: сервер подставляет набор ответов с заранее заданным числом верных, чтобы сразу показать разбор и маршрут. Не задан — эндпоинта нет (404), сочетание ничего не делает. **После защиты переменную нужно убрать**: с ней любой, кто знает сочетание, накрутит себе балл. |
| `KSPOYA_DEMO_MIN` / `KSPOYA_DEMO_MAX` | нет | Границы целевого балла демо-режима. По умолчанию 20 и 30 из 40 — это B1/B2. |

## Сборка и запуск на Render

```
Build command:  go build -o rootry .
Start command:  ./rootry
```

Статика (`static/`) отдаётся самим приложением, отдельный веб-сервер не нужен.
Рабочий каталог должен быть корнем репозитория — сервер ищет `./static`.

## База данных

Порядок ровно такой, файлы выполняются по одному разу:

```
schema.sql
migrations/001_mastery.sql
migrations/002_backfill_completed.sql
migrations/003_classes.sql
migrations/004_research.sql
migrations/005_kspoya.sql
migrations/006_lessons.sql
migrations/007_svg_items.sql
```

В Supabase — через Dashboard → SQL Editor. Локально:

```bash
for f in schema.sql migrations/*.sql; do psql "$DATABASE_URL" -f "$f"; done
```

Миграции 005 и 006 раньше лежали в корне (`supabase_migration_kspoya.sql`,
`supabase_migration_lessons.sql`) и запускались руками отдельно от остальных.
База, поднятая по инструкции «schema.sql + migrations/», оставалась без таблицы
`kspoya_sessions`: тесты КСПОЯ и рейтинг молча отдавали пустые списки, а в логах
копилось `relation "kspoya_sessions" does not exist`. Теперь это обычные
миграции, и порядок один и тот же на проде и локально.

**Уже развёрнутой базе ничего доделывать не нужно:** все операции в 005 и 006
идут через `IF NOT EXISTS`, повторный запуск безопасен.

Миграция 007 переводит аватарки и значки со старых эмодзи на
идентификаторы. Она не обязательна: сервер понимает оба формата
(`internal/store/legacy.go`) и пишет уже в новом. Смысл 007 — привести
данные к тому же виду, в каком их ждёт код, чтобы слой совместимости
когда-нибудь можно было убрать. Запускается одной транзакцией, повторный
запуск ничего не меняет.

## Локальный запуск

```bash
go run ./devtools/localdb          # поднимает локальный PostgreSQL в devtools/localdb/.pgdata
DATABASE_URL=... JWT_SECRET=dev go run .
```

Демо-аккаунт создаётся при первом старте: `demo` / `demo123`.

## Проверка перед показом

```bash
go build ./... && go vet ./... && go test ./...
node static/lessons/validate.js   # 74 темы, 260 блоков теории, 437 заданий
node static/practice.test.js
```

Что стоит открыть руками: дерево (`/tree.html`), урок из дерева, тест КСПОЯ,
ассистента (`/assistant.html`), профиль (`/profile.html`) — там же план
повторения и тетрадь ошибок, кабинет учителя (`/class.html`) и админку
(`/admin.html`), раздел «Исследование».

Отдельной вкладки «Сегодня» больше нет: план повторения и работа над
ошибками переехали в профиль, а после входа платформа открывает игры.

## Внешние зависимости фронтенда

Font Awesome и Google Fonts грузятся с CDN, d3 — из `static/vendor/`.
У Font Awesome прописан локальный запасной вариант (`static/vendor/fa/`).

Аватарки, значки и знаки уровня — свои SVG-файлы в `static/img/`
(`avatars/`, `badges/`, `ranks/`), генераторы лежат в `tools/`. Внешний
сервис dicebear больше не используется, эмодзи в интерфейсе не осталось:
раньше и то и другое зависело либо от сети, либо от шрифта операционной
системы, и на чужом компьютере экран выглядел иначе, чем на своём.
Мелкие иконки интерфейса — векторы из `static/icons.js`.

Если в зале не будет интернета, сайт останется рабочим и читаемым;
сломаются только начертания шрифта Montserrat, которые заменятся
системными. Ассистенту интернет нужен всегда — он ходит в Gemini.
